# 偏好模板与存档协议（V1.5.3）

生成提示词时按本协议读取模板；用户表达偏好时按本协议写入。本协议不改变六步流程、九区域母版、知识库和编译门禁。

## 1. 唯一原则：模板取自母版，不取自提示词

母版是设计真相，提示词是母版的译本，永远在下游。因此：

- 一条模板记录的是**母版某个维度的设计方向**（例如光影区的光源方向、性质、明暗比、冷暖关系），保存为 `source_items`：每项 `facet` + `value`，来自母版条目。
- 应用模板时，按维度**回填进新母版的对应区域**，再由宿主重新编译提示词。
- **禁止**把提示词里的措辞、句子、形容词当作模板内容。同一个设计可以编译成很多种说法，句子不是设计。

## 2. 模板结构

```json
{
  "id": "T0002",
  "name": "性感",
  "dimension": "subject",
  "attributes": ["胸部体积明显", "腰线内收", "髋部宽", "黑色丝袜"],
  "apply_mode": "default_fill",
  "scope": {"scene": "*", "model": "*"},
  "default_on": false,
  "status": "active",
  "source": "user_specified",
  "source_items": [{"facet": "body_contour", "value": "腰线内收"}],
  "evidence": ["F0003"],
  "note": "用户指定",
  "created": "...",
  "updated": "..."
}
```

- `dimension`：`subject` / `lighting` / `palette` / `camera` / `material`。不同维度可同时生效；**同一维度只允许一个 `default_on`**。
- `apply_mode`：
  - `default_fill`：母版该维度为空且本轮未指定时自动填充。
  - `prefer`：同类场景里倾向采用，允许被本轮要求覆盖。
  - `avoid`：设计时排除；`avoid` 模板 `active` 即始终生效，不设 `default_on`。
- `scope.scene` / `scope.model`：`*` 表示不限。模型经验只挂在该模型名下，不跨模型传播。
- `source`：`user_specified`（用户明说）/ `master_extracted`（从母版提取，必须有 `source_items`）/ `inferred`（推断，出生即 `pending`）。

**模板名可以是“性感”“高级感”；属性必须是可见事实。** 属性里出现评价词会被程序拒绝。原因很实际：评价词进不了提示词，写了等于没写。

## 3. 三个开关

| 开关 | 关闭后 |
|---|---|
| `record` | 拒绝一切新增写入（模板、存档、推断） |
| `apply` | 查询仍可用，但设计时不得使用任何模板 |
| `remind` | 不再在回答末尾输出生效提示 |

`prefs set --key record --value off` 等。

## 4. 生成前：怎么用模板

1. 运行 `prefs query --scene <场景类型> --model <目标模型>`，取 `defaults / prefer / optional / avoid / pending`。
2. `defaults`：仅当母版该维度为空且本轮没有指定时填充。用户本轮指定了就别填。
3. `prefer`：作为倾向参与设计，本轮要求优先；冲突时说明取舍。
4. `avoid`：设计时避开。**不得把排除项写成否定句或 Negative Prompt**，要转成实际选用的替代方案。
5. `pending`：不参与设计；查询时按当前场景、模型、维度过滤，只在用户查看时说明“有待确认的推断”。查看全部待确认项使用template list并查看pending状态；query未给场景或模型时，该维度仅匹配不限作用域的模板。
6. 用户说“这次不要默认”，本轮抑制全部 `default_fill`，不写库。

`optional` 是已启用但未设为默认的 `default_fill`／`prefer` 模板集合，不是第四种作用模式。里面的 `default_fill` 不得自动填充，仅用户选择后应用；`prefer` 仍按倾向规则处理，不能因为重复出现在此集合而重复应用。`template resume` 仅恢复已停用且已获必要确认的模板；pending 推断必须由用户明确确认后用 `template on` 激活。

## 5. 生成后：怎么记录

先判断用户说的是哪一种，再决定写哪个库：

| 用户表达 | 处理 |
|---|---|
| 对某条产出的**整体**赞赏（“这张真好”“喜欢这个结果”） | `archive add`：存母版快照 + 提示词原文 + 四档评价。**不建模板，不影响设计偏好。** |
| **明确指向某个设计**（“我喜欢这个光线”“以后都用这种构图”） | 从**母版**提取该维度的设计方向，`template add`，`source=master_extracted`。 |
| 明确陈述长期要求（“以后都中文”“别用红绿配”） | `template add`，`source=user_specified`。“默认”用 `default_fill`，“喜欢/倾向”用 `prefer`，反感用 `avoid`。 |
| 指出某模型下某元素出问题 | `template add`，`apply_mode=avoid`，`scope.model` 收紧到该模型。 |
| 只说“一般”“不喜欢”，没有指向 | 什么模板都不建；可以只留一句原话给用户参考。 |

**不得从反馈里推断偏好。** 用户没说出来的东西，不写成模板，连 `pending` 也不写。

## 6. 推断是独立任务

只有用户明确要求（“看看我存的那些提示词，总结我偏好什么”）时才执行：

1. `prefs archive` 里的记录作为依据，读的是**母版**，不是提示词原文。
2. 产出候选：`prefs infer --input`，全部落为 `pending`，`evidence` 指向存档 ID。
3. 逐条向用户说明“这条来自哪几次、我建议怎么用”，等待确认。
4. 用户确认后 `prefs template on --id`，才可能生效。

推断与出词流程完全独立：**生成过程中绝不触发推断**。

## 7. 冲突与优先级

本轮明确要求 > 用户硬约束模板 > 普通模板 > 我的补全。

- 本轮要求与模板冲突：服从本轮，说明被覆盖的模板，不自动删除它。
- 用户说“以后都这样”才是修改长期规则；一次例外不删旧模板。
- 一条模板被本轮反复推翻时，提示用户是否 `off` 或 `stop`。

## 8. 提醒

每轮回答末尾一行，列出本次实际生效的模板：

```
[模板生效：性感｜窗侧柔光]
```

没有生效模板就不输出这一行。用户可以用 `remind off` 关闭。

## 9. 禁止与边界

- 不把模板、ID、偏好原文写进提示词正文。
- 不用负向词落实 `avoid`。
- 不把模板属性写成评价词或抽象情绪。
- 不从提示词反推模板属性。
- 不在生成时推断偏好。
- 不改六步流程、知识条目、母版结构、编译检查——本协议只作用于“设计输入”和“编译语言”两层。

## 10. 没有 Python 时

模板能力整体不可用。必须说明“偏好记录不可用，本次按会话内理解处理”，不得声称已保存。会话内可以继续遵守用户本轮说过的偏好，但不得声称跨会话记住。

数据目录必须在技能源码之外，并位于宿主实际可写、跨会话不变的路径。程序拒绝写入技能目录。
