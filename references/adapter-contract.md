# 基础 Model Adapter

自然语言编译继续通用优先；只落实用户已确认的模型与表达规则，不宣称完整模型能力已迁移。路由配置为 [registry.json](../adapters/registry.json)，本地 [adapter.py](../scripts/adapter.py) 从配置读取画幅排版；语言和自然语言组织由宿主LLM执行。MOSS显式Layout另有结构检查；宿主无Python时仍可创作，但不能宣称已经执行程序校验。
允许翻译、语序、分段、等义合并及交付排版；不得改变主体数量、动作、场景、空间、主光、颜色或已确认风格。
用户未指定目标时可以交付通用版，不猜专属参数；默认风格不反复提问。

## GPT正文语言（GPT-01，用户已确认）

适用于当前已实现的 `gpt-web / gpt` 路由：

- 最终提示词正文默认使用中文自然语言；用户明确指定其他语言时，按其要求输出。
- 画面内需要显示的文字逐字保留原文及原始语言，不随提示词正文翻译。
- 知识库现有英文示例保持原样。正文语言不改变既有画幅排版：GPT画幅仍由已确认母版决定，按本路由在代码块内末尾表达。
- 这项语言规则由宿主LLM在编译与语义复核时执行；本地Python Adapter只做既有排版，不自动翻译，也不能证明宿主已遵守语言要求。

## GPT提示词组织（GPT-02，用户已确认）

适用于当前已实现的 `gpt-web / gpt` 路由，由宿主LLM在编译和语义复核时执行：

- 根据画面复杂程度组织提示词。简单画面使用连贯自然语言；复杂画面可以按场景、主体、细节和约束分段，必要时使用简短标题，不强制固定顺序或四段模板。
- 长度由实际设计信息决定，不能为了简短删掉已确认内容。九区域母版不机械转换为九段提示词；内部编号和审核记录仍不进入正文。
- 此规则只指导表达组织，不改变设计事实、GPT-01语言约定或既有画幅排版；本地Python不判断画面复杂程度，也不保证分段会改善生成结果。

官方核实：2026-11-01，[OpenAI Image prompting — Prompting fundamentals](https://developers.openai.com/api/docs/guides/image-prompting#prompting-fundamentals)。官方建议复杂请求分段并选用易读、易维护的格式；实际图像效果需另行验证。

## Grok提示词组织（GROK-01，用户已确认）

适用于当前已实现的 `grok-web / grok` 路由，由宿主LLM编译和复核：

- 正文优先交代已确认的主体、动作或状态，以及与环境的关键关系，再展开光色、材质和构图。
- 主体及环境、细节与视觉重点、艺术指导、光线、色彩、构图六类信息作为组织参考，不强制六段模板，也不为调整顺序删减设计。
- 这是对已确认设计的表达组织，不授权重设计或调整人物约束，不将其认定为此前人物约束减弱的根因。既有画幅继续通过网页端外部设置交付，不在正文重复。

官方核实：2026-11-01，[xAI Image Prompting Guide](https://docs.x.ai/developers/model-capabilities/images/prompting-guide#write-the-subject-first)。官方针对 `grok-imagine-image-2.0` 建议主体先行；这是编译参考，不证明当前网页端后端身份或出图效果。未迁移API或图像编辑能力。

## Midjourney正文表达（MJ-01，用户已确认）

适用于当前已实现的 `midjourney / mj` 路由，由宿主LLM编译和语义复核：

- 正文直接描述成品画面，避免“请帮我画、请让画面更高级”等对话式指令和审美解释。
- 可以使用紧凑的自然语言短句，不强制改成标签串。精简重复表达，不删已确认设计，不设统一字数上限。
- 不把九区域字段、内部讨论和审核记录抄进正文。既有画幅由Adapter在块内末尾输出 `--ar W:H`，不改动其他参数和语言约定。
- 规则约束表达方式，不证明模型执行效果，也不允许通过删除设计事实取得完整性检查pass。

官方核实：2026-11-01，[Midjourney Prompt Basics](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics)。官方建议清楚、简短的画面描述，避免冗长指令，同时说明重要细节需要保留、细节减少会降低控制；未规定本项目通用字数上限。实际图像效果待验证。

## Midjourney加强压缩（MJ-02，用户已确认）

适用于 `midjourney / mj`，在既有编译与语义复核中执行，不增加内部协调或自动重试预算：

- 直接从已确认母版编译紧凑版本，不先生成长篇通用Prompt再做少量删改。通用优先仍指使用自然语言和共同设计事实，不要求先交付一份长稿。
- 同一视觉事实只表达一次；用简明关系合并主体、动作、服装、位置等关联信息，删除铺垫、解释、重复强调和无视觉作用的修饰，不把不同事实误并成一个含混词。
- 不逐项展开九区域，不为覆盖专业领域而补写描述；只表达母版中实际需要成图的信息。已确认可编译事实仍须完整覆盖，不因归入某个区域或被认为次要而自动删除。
- 压缩到继续缩短就会损失关键含义为止，不设统一字数上限。用户明确要求、具体画面文字、数量和设计事实之间的关系保持原义；完整性检查继续适用，fail或uncertain不得放行。
- 若保留全部设计后仍过长，应回到总导演，提出具体的次要设计删减建议和损失，由用户确认修改后的具体母版版本后再编译。Adapter不得自行删减或把遗漏登记为pass；不能直接沿用旧母版确认和旧成品复核。

本条加强表达压缩，不修改人物约束、其他模型的压缩策略或既有 `--ar` 交付位置。是否改善图像效果尚待实际对照验证，不把长度直接判作失败的唯一原因。

依据：2026-11-01已读取的[Midjourney Prompt Basics](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics)建议简短直接、保留重要细节；以上压缩步骤及母版确认边界是用户批准的产品实施规则，不冒充官方字数标准。

## Midjourney正文语言（MJ-03，用户已确认）

适用于 `midjourney / mj`：最终提示词正文默认使用简洁中文；用户明确要求英文或其他语言时按其要求输出。继续执行MJ-01直接画面描述和MJ-02加强压缩规则，不因切换语言扩写或改变设计。

画面内文字逐字保留用户指定原文及原始语言，不随正文翻译；知识库现有英文示例保持原样。既有画幅仍在块内末尾使用 `--ar W:H`。

这是用户确定的产品语言约定，不宣称中文已实测优于英文。语言选择和语义复核由宿主LLM执行；Python Adapter不自动翻译，也不能证明宿主已遵守语言要求。正文或路由配置改变后，按Compiler契约重新复核实际最终成品，不沿用旧pass。

## Midjourney Raw与Stylize（MJ-04，用户已确认）

适用于 `midjourney / mj`，由宿主LLM结合已确认设计判断：

- Raw（`--raw`）减少Midjourney自带的风格处理；Stylize（`--s`或`--stylize`）控制模型风格化介入。较低Stylize倾向贴近描述，较高值给予更多艺术发挥，但可能偏离具体细节。
- 需要减少模型自行发挥、加强具体描述遵从时，可以建议Raw或降低Stylize；希望保留更多艺术发挥时谨慎选择，不把某套参数设为固定配方，也不保证开启后一定改善效果。用户明确指定的设置优先，不擅改其选择。
- 默认以官网最新主力模型的能力说明为依据选择具体取值，不以平台默认值代替设计判断；未知时说明未知，不编造推荐数值。参数不改变母版视觉事实，仍需按既有Compiler契约复核。
- 确定采用的参数在同一代码块末尾参数区表达，可放在既有 `--ar W:H` 之前，不在参数后追加普通描述，不在块外重复。使用本地工具时，参数文本置于候选最后一段，Python仍只执行现有排版，不自动选择Raw或Stylize；最终成品须重新复核，不能沿用调整前的pass。

官方核实：2026-11-01，[Raw](https://docs.midjourney.com/hc/en-us/articles/32634113811853-Raw)、[Stylize](https://docs.midjourney.com/hc/en-us/articles/32196176868109-Stylize)。本条补充选择知识与交付说明，不宣称已经验证实际图像效果，也不迁移其他专用参数能力。

## 本地开源Krea 2编译（KREA-01，用户已确认）

## 语言偏好覆盖（H-01，用户已确认）

用户长期语言偏好（例如“提示词一律中文”）覆盖各路由的 `default_prompt_language`，包括 Qwen Image 2.1 的英文默认。规则只有一条：**语言可换，结构不换。**

- 换的只是正文语言；该路由的表达组织、单段或分段要求、观察式或自然语言风格、画面文字逐字保真、比例位置一律不变。
- Qwen 改中文后仍是单段、第三人称、现在时、陈述口吻的观察式描述，不退回流水句、标签串或Markdown结构。
- 覆盖发生时在交互层提示，例如末尾一行 `[语言：中文（路由默认英文）]`；用户可关闭提醒。
- 这是产品语言约定，不宣称中文在该模型上必然优于英文；实际效果未验证。程序不自动翻译，也不证明宿主已遵守。



仅在目标明确为Qwen Image 2.1文生图、当前完整母版版本已获用户确认后使用。文字改写由宿主LLM执行，不需安装或调用额外改写模型。

- 保留专用观察式表达：以第三人称、现在时、陈述口吻描述已经呈现的成品画面，正文为连续单段，不写给绘图模型的命令或创作解释。默认英文；用户长期语言偏好覆盖时改用该语言，结构不变（见H-01）。画面内文字逐字保留原语言、标点和空格。
- 开头交代母版已有的媒介、主体、环境或色彩关系；多区域画面按实际区域有顺序地描述，单主体画面按主体及其周围关系展开。位置来自母版，不强凑位置短语数量，也不为覆盖四角添加元素。
- 细节与长度由实际画面需要决定，不硬凑20句或400–500英文词，不套用MJ加强压缩策略。母版没有的设计不发明，已确认事实及关系不删改；知识库英文示例保持原样。
- 最终一个代码块只放成品描述，不输出PE改写器JSON。比例由Adapter在代码块外列出，按本地工作流width/height等实际设置生效；正文不写比例行，不编造像素尺寸，不按题材回落3:2或2:3。

工具选择 `qwen-image-2.1`（别名 `qwen-image-2.1-t2i`、`qwen-image`）。各segments用一个空格连接为单段；每段的事实ID仍分别保留，合并不等于放宽完整性检查。宿主写作时保持单段，若画面文字原文自身含换行，其逐字保真优先，不能为排版改写文字。最终成品仍须逐项语义复核，fail或uncertain不得放行。

官方核实：2026-11-01，[PE-T2I模型卡](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-T2I)、[官方改写指令](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-T2I/blob/main/system_prompt.txt)、[图像模型与工作流](https://github.com/QwenLM/Qwen-Image-2.1)。英文观察式是所采用的官方改写风格，不代表图像模型只能接收英文；单段与长度取舍、代码块交付按用户批准的产品规则执行。官方改写器中自行补设计、按题材默认比例的逻辑不接管本产品母版。

## 接口与交付边界

Gemini／Nano Banana、Seedream及MOSS的具体编译、文字与Layout规则见[三组路由说明](model-routes.md)，遇到相应目标时读取，不将知识术语或整份文档抄入Prompt。

本版不提供API路由或API调用。SDXL、Pony、Illustrious、Anima及FLUX（含Klein）已由用户明确不纳入本版；不得静默回退generic冒充支持，也不从只读旧版自动补回这些路由。该范围决定不修改V1.4.0或删除其能力资料。
