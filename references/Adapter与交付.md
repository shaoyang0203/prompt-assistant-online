# Adapter 与交付

只在内部使用。Adapter 只改变表达，不重新设计画面；母版内容一律以 SKILL.md 为准。

## Adapter 总合同

Adapter 只能改变：

- 语言
- 长度
- Prompt 结构
- Tags
- 平台参数
- 比例表达
- 模型专属语法

Adapter 不得改变：

- 主体
- 动作
- 场景
- 核心构图
- 主光
- 色彩方向
- 已确认的艺术方向

## LoRA 与 Negative Prompt 边界

LoRA 属于 Adapter 层。

只使用用户或可靠资料提供的：

- LoRA 名称
- Trigger Words
- 推荐权重

不自行发明。

视觉母版和所有 Adapter 输出一律不包含 Negative Prompt，标准按 SKILL.md「强制正向可见事实」执行；任何模型、工作流或用户要求都不得触发否定式提示词的生成、交付或附加。

CFG、步数等只在用户明确要求且具体工作流需要时提供；普通正向 Prompt 不因 Z-Image Turbo 或 Base 分叉。

- 建议宽高比
- 具体像素尺寸
- 用户询问原因，或比例选择并不直观时的简短理由

只有具体工作流确实区分抽卡尺寸和高质量尺寸时，才分别列出两组数字；否则只给一个主要建议尺寸。无法确定可靠像素尺寸时，只给宽高比，并在代码块外简短注明像素尺寸需按具体工作流设置；不编造数字，也不为此追加提问。

- 具体模型
- 模型版本
- 工作流
- 可靠分辨率信息

在线生图模型不适用本节的像素尺寸部分：按 SKILL.md「默认对外输出」只给建议宽高比，不给像素尺寸。

## GPT 与 Grok

使用自然语言。

保留完整：

- 空间
- 动作
- 构图
- 光影
- 材质

摄影参数只在有实际视觉收益时加入。

GPT 与 Grok 都以可见结果为核心组织自然语言。除非相机品牌、焦段或曝光参数会直接改变透视、景深、运动表现或光线结果，否则不机械堆叠器材参数。

最终交付使用一个代码块。先写完整 Prompt，再在同一代码块末尾加入：

- 建议宽高比

不得加入具体像素尺寸。未另行规定交付排版的在线生图模型，默认沿用这一布局。

## Midjourney

把视觉母版压缩成简洁、具体、视觉导向的 Prompt，只描述最终希望出现的画面。

默认优先英文。

优先保留真正影响画面的高控制信息：主体、环境、构图、动作、光线、色彩、材质、媒介与风格。词序按当前画面自然组织，不预设固定排列——哪一项对结果影响最大，就放在最前面。

删除解释性语言、冗余同义词堆叠和对画面没有控制作用的词。用户明确指定的重要细节必须保留，简洁不等于删去有效视觉信息。

比例使用：

--ar 2:3

最终交付使用一个代码块。把 `--ar` 放在 Prompt 末端；其他 Midjourney 参数只在确有需要且有可靠依据时追加。不要把比例或参数拆到代码块外，也不要提供具体像素尺寸。

## SDXL 系列

本分类包含 SDXL 通用工作流，以及 Pony、Illustrious、Anima 三个常用分支。同属一个分类不代表它们共享完全相同的质量标签、Trigger Words、提示词格式或尺寸建议；必须以具体 checkpoint 和可靠模型卡为准。

### SDXL 通用

根据具体 checkpoint 选择：

- Tags
- Natural Language
- Hybrid

不把所有 SDXL 系列模型统一写成 Pony 格式。

### Pony

优先英文 Tags。

顺序：

- quality / style
- subject count
- adult character
- appearance
- hair
- clothing
- pose
- expression
- environment
- lighting
- composition

保留用户提供的 LoRA 和 Trigger Words。

不同 Pony 模型的 score 体系可能不同，不自行假定。只有用户提供具体版本，或可靠模型卡明确要求时，才按原顺序加入 `score_9`、`score_8_up` 等质量标签；不知道版本时不得把某个 Pony 分支的标签当成全系列通用规则。

### Illustrious

根据具体 checkpoint 或模型卡决定使用英文 Tags 或混合格式。保留用户提供的角色、风格、画师标签、LoRA 和 Trigger Words；除非具体模型明确要求，不套用 Pony 的 score 标签体系。

### Anima

优先英文 Tags。

风格优先级较高。

“Anima”可能指不同模型或工作流，不自动等同于 NovelAI，也不凭名称推断其写实能力、画师标签体系或参数格式。具体版本未知时保留通用表达和用户已给出的标签，不添加未经确认的质量标签或尺寸。

画风未指定时根据用户已有内容直接设计；只有明确媒介要求明显冲突时才询问。

不机械加入摄影器材参数。

## Z-Image 与 Krea 2（中英混合短 Prompt 路由）

用户说“ZIT”、指明 Z-Image（含常用 Turbo 与 Base）或 Krea 2 时，走同一条路由，不因版本不同分叉写法。这条路由的 Turbo 与 Base 在提示词编译层共用以下全部规则。

### 语言分工

采用中文自然语言骨架 + 英文 Tag 补强的混合写法。这不是把 Prompt 全译为英文，也不是退回英文 Tag 墙。

- 中文自然语言负责需要清楚叙述关系的内容：主体、身份、数量、动作与手部任务、服装与道具、场景与空间层次、主光逻辑与色彩关系。
- 英文 Tag 负责一词命中成像结果的锚点：风格与媒介、材质与表面、胶片与印片响应、镜头与景深术语、模型词库中的专名表达，以及用户已给出的 Trigger Words 与角色、画师、checkpoint 标签。
- 用户提供的英文专名、LoRA 名称、Trigger Words 原样保留。
- 中文承担结构与正确性，英文承担精度与成像气质；不重复用两种语言说同一事实，也不为凑英文密度削去画面需要的内容。

### 短小精悍

短来自选词精度，不来自删内容。

- 一句中文只承担一个作用，一个 Tag 只承担一个作用。
- 删除同义重复、解释性语句、故事与心理暗示、无视觉作用的装饰形容。
- 一个强语义已经完成的控制不再重复补写（遵循最小充分约束）。
- 用户明确指定的服饰、纹样、首饰、妆发与结构细节属于硬要求，不列入压缩对象。
- 不规定固定词数或字数阈值；长短由信息预算决定。

### 推荐顺序

1. 中文骨架：主体 → 外观 → 动作 → 环境 → 构图 → 光影。
2. 英文 Tag 收束：风格、材质、成像结果集中放在末段，形成气质收尾。

### 其他约定

- 需要画面内出现中文或英文文字时，原样保留目标文字并明确版面位置。
- Z-Image-Edit、Omni 类与 Krea 的编辑任务属于编辑或生成/编辑任务，按实际任务处理，不直接套用本路由。
- 用户要求 CFG、步数、尺寸等工作流参数时，只使用有可靠依据的信息；依据不足则说明无法确定，不因参数未知暂停出词。普通正向 Prompt 不询问 Turbo 或 Base。
- 用户要求 Negative Prompt 时不生成负向内容，直接把有效约束转换为正向可见事实。
- 除非实际工作流明确支持，不主动加入 (word:1.2) 等 Stable Diffusion 式权重语法。

### Krea 2 的两种方式与参考图

- 探索模式：用户想找方向时，保留简短主题种子和少量关键约束，让模型提供多样视觉方向；不过早用完整视觉母版锁死所有细节。
- 锁定模式：用户已有明确方向或要求最终 Prompt 时，按本节混合写法写清媒介、主体、动作、构图、光线、色彩和材质。细节越明确，输出范围越收敛。
- Krea 2 自带 Prompt Expander，但本路由不依赖它修复主体、数量、动作或构图错误。视觉母版仍负责内容正确，扩展只允许在已锁定边界内进行。
- 用户提供 Style Reference、Moodboard 或风格参考图时优先利用；可用一张或多张，并控制每张参考的强度与混合。参考图只传递分配给它的风格或情绪职责，避免把人物身份和场景内容无意带入。

### 交付格式

1. 代码块外先写“建议宽高比”。
2. 有可靠像素依据时，在代码块外继续写“建议尺寸”，使用“宽×高像素”形式；无法确定时只给宽高比，并注明像素尺寸按具体工作流设置，不编造数字、不为此追加提问。
3. 下方独立代码块内只写最终 Prompt，尺寸说明不混入 Prompt。

## Qwen Image 2.1（T2I）

触发条件、路由优先级和交付形态的唯一规则出处是 SKILL.md「Qwen Image 2.1 T2I 路由」；英文长描述的具体写法以 `Qwen-Image-2.1-T2I.md` 为准。本节只登记该 Adapter 的合同边界、比例判断与 JSON 交付。

### 适用范围

- 只处理 Qwen Image 2.1 文生图。
- 图像编辑、换装、换脸、换背景、合成、扩图等任何依赖原图内容的任务不进入本节：不调用 T2I JSON 编译器，不引入 Qwen 编辑机制（画布跟随、`<image>` 编号、`ratio_follow`、原图像素保真），并按 SKILL.md「出词与提问边界」在正常对话中简短说明当前 Qwen 路由只覆盖文生图。
- 输入图仅作抽象风格参考且任务是从零生成新画面时可按文生图处理，但仍不引入上述编辑机制。

### Adapter 合同（Qwen T2I）

在「Adapter 总合同」基础上，本 Adapter 只允许改变：

- 输出语言（一律编译为英文）
- 描述视角（观察者陈述成品画面）
- 信息展开程度与句子组织方式
- JSON 数据结构
- 画幅字段表达（`wh_ratio`）

不得改变：

- 用户硬要求
- 主体和数量
- 人物身份
- 动作时间点
- 场景
- 核心构图与空间关系
- 主光逻辑
- 色彩方向
- 材质设计
- 已确定的风格和媒介
- 画面内文字
- 已经确定的画幅

输入是视觉退火完成后的统一视觉母版。母版没写的，本 Adapter 不发明；母版已定的，本 Adapter 不改写。“画什么”由母版决定，“怎么说成英文 JSON”由本 Adapter 决定。

### 英文观察式长描述（要点）

- 始终英文；画面内需要显示的文字保留原始语言。
- 观察者视角描述成品画面：现在时、第三人称、陈述语气；不出现 `you`、`create`、`generate`、`make sure`、`the AI should` 等命令式表达。
- 连续单段，无换行；通常约 20 句、400–500 英文词，单一安静主体可略短，复杂版式或大量画面文字可略长。
- 开头一句点明媒介、风格、主体、背景或色彩关系，适合时说明横纵向；随后按分区巡游或单一主体巡游展开，位置短语充足并覆盖四角、边缘与中心；光照有明确交代；最后一句整体收束，之后不再追加第二个总结。
- 服从「强制正向可见事实」：无否定式画面指令、无 Negative Prompt；无 `masterpiece`、`8K`、`award-winning`、`highly detailed` 等空泛质量词；无模型名称、D/P/C/R/S 代码、导演或摄影师名、片名、创作解释、平台参数。
- 完整写法见 `Qwen-Image-2.1-T2I.md`。

### 比例判断

- 用户明确指定比例时完全服从，并转换为最简整数比。
- 用户未指定时，按「尺寸与交付」的题材默认表与画面内容选择，并叠加 Qwen 专用缺省：横向题材 `3:2`、纵向题材 `2:3`、方形徽章/图标/专辑封面/居中标志 `1:1`、宽银幕或演示画面 `16:9`、手机屏幕或竖长横幅 `9:16` 或 `1:2`；其他比例仅在主体形状或版式确实需要时使用。
- `2K`、`4K`、`8K` 只表示质量意图，不用于推断比例，也不得进入任何输出字段。
- 比例只存在于 `wh_ratio` 字段；本节不适用「尺寸与交付」中的像素尺寸建议——Qwen 路由任何情况下不输出像素尺寸。

### 严格双字段 JSON 交付

最终输出是一个单行、严格有效的 JSON 对象：

{"rewritten_prompt":"<英文成品画面描述>","wh_ratio":"<W:H>"}

- 不使用 Markdown 代码块；JSON 前后没有任何文字，不输出视觉母版、建议尺寸、解释或提问。
- 字段固定且只有两个，不增加第三字段，不输出 `ratio_follow`。
- `rewritten_prompt` 内不含比例、像素、分辨率信息；其中的画面文字直双引号必须正确转义，保证标准 JSON 解析器可直接解析。
- 本交付形态覆盖 SKILL.md「默认对外输出」中在线模型的代码块与正文比例排版规则，仅对 Qwen Image 2.1 文生图路由生效。

## 未登记模型

依据已有可靠信息判断名称指向的模型或工作流类型，采用适合的自然语言、Tags 或平台语法。名称有歧义或信息不足时，直接采用通用自然语言，不猜测模型家族、质量标签、专用参数或尺寸。尺寸未知时只推荐比例，并在代码块外注明像素尺寸按具体工作流设置。
其他未登记的中文自然语言友好模型可参照「Z-Image 与 Krea 2（中英混合短 Prompt 路由）」的混合写法与交付格式。
不因模型未知提问；只有用户明确要求明显冲突时才确认。视觉母版的画面内容保持一致。
