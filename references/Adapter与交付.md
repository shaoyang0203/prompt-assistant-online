# Adapter 与交付

Harness 元信息遵循 SKILL.md：每轮先显示实际状态，首次另有开场与启用说明，均位于代码块外。以下交付条款只规定 Prompt 本身。

只在内部使用。Adapter 只改变表达，不重新设计画面；母版内容一律以 SKILL.md 为准。

## Adapter 总合同

输入必须是已经按 [素材到画面的设计合同](design-contract.md) 验收的视觉母版，不接收用户原文代替设计结果。发现关键设计仍缺失时返回六步流程对应步骤；不得自行翻译原文并把翻译稿视为母版。短自然语言、短词和 Tags 只压缩表达，不减少已确定的画面关系。用户明确仅翻译或纯格式转换时，依照该局部任务处理，不擅自增加设计。

Adapter 只能改变：

- 语言
- 长度
- Prompt 结构
- Tags
- 平台参数
- 比例表达
- 模型专属语法

Adapter 不得改变：

- 主体
- 动作
- 场景
- 核心构图
- 主光
- 色彩方向
- 已确认的艺术方向

## LoRA 与 Negative Prompt 边界

LoRA 属于 Adapter 层。

只使用用户或可靠资料提供的：

- LoRA 名称
- Trigger Words
- 推荐权重

不自行发明。

视觉母版和所有 Adapter 输出一律不包含 Negative Prompt，标准按 SKILL.md「强制正向可见事实」执行；任何模型、工作流或用户要求都不得触发否定式提示词的生成、交付或附加。

CFG、步数等只在用户明确要求且具体工作流需要时提供；普通正向 Prompt 不因 Z-Image Turbo 或 Base 分叉。

## GPT Image

本节只在最终生成阶段生效；选择 GPT Image 不跳过创意探讨。固定开场、方案讨论与生成触发条件仍按 SKILL.md。本路由只覆盖文生图。

### 产品与接口边界

- **ChatGPT 网页端**：用自然语言描述画面；宽高比通过界面比例选择器设置，或在提示词中写明比例。网页端不暴露 API 的 `size`、`quality`、`background` 等参数，不把这些参数写进提示词。
- **GPT Image 模型**：当前主力为 GPT Image 2.5 Sunburst（`gpt-image-2.5-sunburst`，质量优先）与 GPT Image 2.5 Flare（`gpt-image-2.5-flare`，速度优先）；GPT Image 2（`gpt-image-2`）仍可用。
- **Images API**：使用 `generate` 端点直接生成图像，适合需要精确控制提示词与请求配置的工作流。
- **Responses API 图像生成工具**：可在对话中生成图像；官方说明该工具可能自动改写或优化提示词。需要逐字控制提示词时，使用 Images API 的直接调用。

API 请求参数与提示词正文必须分开。只有用户明确要求 API 调用格式或工作流配置时，才提供参数；不要把 `size`、`quality`、`background`、`output_format`、`n` 写成模型必然理解的普通提示词语句。

### 提示词编译

- 使用自然语言，优先写清主体、动作、环境、构图、风格、光线、材质与关键约束。复杂任务可以展开细节，但不把提示词变成重复形容词的堆积。
- 官方建议复杂提示可按场景、主体、细节、约束分段组织；这是可选参考，不是固定句式或固定字段要求。简单任务无需套用全套分段。
- 不规定所有 GPT Image 提示词必须同样长；长度由画面信息决定。不得因为追求简洁而删掉关键构图、空间关系、光线设计与用户硬要求。
- 画面内文字写明原文与语言；需要保留的精确文字不翻译、不概括。
- 摄影器材参数只在确实改变透视、景深、运动表现或光线结果时加入；不以器材参数数量衡量质量。

### 参数与尺寸

以下为 API 设置，不是提示词正文；网页端只通过比例选择器或自然语言比例表达。

- 常用尺寸：`1024x1024`、`1536x1024`、`1024x1536`。GPT Image 2.5 与 GPT Image 2 支持自定义 `宽x高`：宽高均为 16 的倍数，宽高比在 1:3 到 3:1 之间，单边不超过 3840 像素，总像素在 655,360–8,294,400 之间；超过 2K 的分辨率属于实验性能力，不默认承诺。
- `quality`：GPT Image 2.5 支持 `low`、`medium`、`high`、`xhigh`、`max`、`auto`；更早的 GPT Image 模型最高支持 `high`。不要把所有型号的质量档位写成同一套。
- `background`：`transparent`、`opaque`、`auto`；透明背景需配合 `png` 或 `webp`。
- `output_format`：`png`、`jpeg`、`webp`。
- `n`：按当前 API 文档支持 1–10；只有用户明确要求多张时才设置。
- 不把 API 参数写进代码块内的提示词正文；用户要求 API 配置时，在代码块外单独列出。

### 交付

网页端：最终提示词放入一个代码块，建议宽高比写在代码块内 Prompt 末尾，并说明该比例是文字建议、实际可在界面选择器设置；不输出像素尺寸。

API 工作流：代码块内只放提示词；`size`、`quality`、`background`、`output_format`、`n` 等参数在代码块外单独列出，且仅在用户明确要求时提供。

## Grok Imagine

本节只在最终生成阶段生效；选择 Grok Imagine 不跳过创意探讨。固定开场、方案讨论与生成触发条件仍按 SKILL.md。本路由只覆盖文生图。

### 产品与接口边界

- 当前模型为 `grok-imagine-image-2.0`，用于文本生成图像。
- **Grok 网页端 Imagine**：用自然语言描述画面。按用户 2026-10-25 的网页端实测，宽高比在输入框外侧的界面控件选择，不依靠提示词文字设置；本 Skill 将推荐比例写在代码块外。这是网页端使用反馈，不混同为 API 参数或 GPT 的交付规则。
- **xAI API**：直接调用图像生成接口，`aspect_ratio`、`resolution`、`quality`、`n` 等作为请求参数，不写进提示词正文。
- **图像生成工具（对话式）**：官方说明由模型决定何时调用工具并撰写图像提示词；用户没有指定比例时，模型可能自行选择。需要精确控制提示词与比例时，使用直接 API。

### 提示词编译

官方提示词指南的顺序可作为编译参考，但不是必须逐项填写的固定表格：

1. 主体及其所在环境。
2. 关键细节与视觉重点。
3. 艺术指导与重要道具。
4. 光线来源、方向及明暗表现。
5. 主体与背景的色彩关系。
6. 构图、画面裁切及清晰度分配。

- 主体与用户硬要求优先；保留已确定的动作、空间关系、构图、主光与色彩方向。Adapter 只编译，不重新设计画面。
- 不机械堆叠摄影器材参数；只有确实改变透视、景深、运动表现或光线结果时才加入。
- 删除冗余，但不删掉关键构图、空间关系、光线和用户明确指定的细节。
- 不把电影感、高级感自动映射为固定色调、颗粒、冷暖对比或构图模板。
- 画面内文字写明原文与语言，不翻译、不概括。

### 参数与尺寸

以下为 xAI API 请求参数，不是提示词正文：

- `aspect_ratio`：`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`2:1`、`1:2`、`19.5:9`、`9:19.5`、`20:9`、`9:20`、`21:9`、`5:2`、`auto`。
- `resolution`：`1k`、`2k`。
- `quality`：`low`、`medium`、`auto`。
- `n`：1–10。
- 网页端不把这些参数写成提示词正文；API 工作流在代码块外单独列出，且仅在用户明确要求时提供。

### 交付

网页端：一个代码块内只放画面提示词；推荐宽高比写在代码块外，并注明在输入框外侧的比例控件中选择。不在 Prompt 末尾写比例行，不承诺通过文字改变画布比例，不输出像素尺寸。GPT 按其独立 Adapter 交付。

API 工作流：代码块内只放提示词；`aspect_ratio`、`resolution`、`quality`、`n` 在代码块外单独列出。

## 路由总则

路由层只负责把视觉母版编译为目标模型的表达、参数与交付排版。画面设计、固定开场、创意探讨、最终生成触发条件、正向可见事实与年龄边界，一律以 SKILL.md 为准；任何路由都不得用“模型特性”绕过这些规则。本文件只覆盖纯文生图；图像编辑与其他依赖原图的任务不在范围内。以下参数与版本依据官方文档核对，核查日期 2026-10-23；官方页面更新后以最新页面为准。文中明确写“官方”的条目来自厂商文档；未标注“官方”的，是本项目的视觉设计与交付约定，不冒充官方语法。

## Midjourney

### 版本与默认值

- 当前默认模型为 V8.2（2026-07-24 起）；V8.1 仍可选；V7 仍可使用；V8.0 已停用；V6.1、V6 与 Niji 7 仍可在明确指定时使用。
- 用户未指定版本时，使用平台默认版本，不主动写 `--v`。只有用户明确要求，或画面确实依赖某版本特性时，才指定版本。
- 不把旧版本教程中的参数、默认值或功能直接套到当前版本。

### 提示词编译

把视觉母版编译为自然、具体、视觉导向的描述，优先保留真正影响画面的信息：主体与人物状态、服装、动作、构图、空间关系、前景遮挡、背景虚实、光线、色彩与材质。词序按当前画面自然组织，哪一项对结果影响最大就放在前面。

默认优先英文；用户明确要求中文或其他语言时，按用户要求执行。

- **精简冗余，不精简设计。** 官方建议简洁，不等于所有提示词都必须短；不得因为追求简洁而删掉精心设计的构图、环境关系与用户硬要求。
- 删除重复形容词、无效的审美解释、没有视觉控制作用的词，以及互相矛盾或无法同时实现的描述。
- 不因为追求电影感或高级感，机械添加胶片颗粒、冷暖对比、背景虚化等元素；这些必须是画面设计的结果。
- 不把摄影术语的数量当作提示词质量指标；不把某个参数的默认值当成所有任务的推荐值。
- 不重新建立一套构图、光线或审美知识；视觉设计系统决定画面，Midjourney Adapter 只负责编译。

### 参数

| 参数 | 作用 | 当前官方取值与默认值 | 使用边界 |
|---|---|---|---|
| `--ar` / `--aspect` | 宽高比 | 默认 1:1；官方兼容表标注最大 14:1，HD 最大 4:1 | 用户指定时优先；旧版本上限不同，不把 14:1 套到 V5 及更早 |
| `--v` / `--version` | 模型版本 | 当前默认 8.2；可选 8.1、7、6.1、6；Niji 用 `--niji 7` | 未指定时不写；只在有明确依据时指定 |
| `--raw` | 降低默认风格介入 | 当前版本支持 | 需要更忠实执行描述时可选，不设为每次必选 |
| `--s` / `--stylize` | 风格化程度 | 0–1000，默认 100 | 不自动加高值；风格强度由画面需求决定 |
| `--c` / `--chaos` | 生成差异程度 | 0–100，默认 0 | 用户没有要求实验性变化时不加高值 |
| `--w` / `--weird` | 非传统、实验性表现 | 0–3000，默认 0；V5 及以上 | 实验性功能，不自动使用；与 seed 不完全兼容 |
| `--p` / `--profile` | 个性化档案 | V6 及以上；个人化档案须已解锁；V7 全局档案可用于 V8.2 | 用户明确要求个性化时才加；不默认替用户选择档案 |
| `--hd` | 原生 2K 输出 | V8.1 及以上 | 用户明确要求高清时使用；HD 的最大宽高比为 4:1 |
| `--exp` | 实验参数 | 存在于当前版本体系，具体取值与效果随版本变化 | 未确认前不写入默认规则，只在用户明确要求时说明不确定性 |
| `--no` | 排除内容 | 官方参数 | 本项目全局规则禁止否定式画面指令与 Negative Prompt；不自动使用 `--no`，用户要求排除时改写为正向可见事实，或说明该参数与全局规则冲突 |

参数统一放在提示词末尾，参数前留空格，参数内不加逗号、句号等标点；参数之后不再追加普通描述。不要把全部参数一次性堆上，也不要把默认值当作推荐值。

### 交付

最终交付使用一个代码块。把 `--ar` 放在 Prompt 末端；其他参数只在确有需要且有可靠依据时追加。不要把比例或参数拆到代码块外，也不要提供具体像素尺寸。不输出 Negative Prompt，不使用 `--no` 规避全局正向事实规则。

- 当前常用模型为 Doubao Seedream 5.0 pro、5.0 flash、5.0 lite，以及 4.5、4.0；具体 Model ID 与可用地区以火山引擎官方文档为准。

### 提示词编译

- 官方建议用简洁连贯的自然语言写明“主体 + 行为 + 环境”；有美学要求时，用自然语言或短语补充风格、色彩、光影、构图。
- 官方 API 建议中文提示词不超过 300 字、英文不超过 600 词；超过后信息容易分散，模型可能忽略细节。该长度是建议上限，不是必须写满。
- 简洁精确通常优于重复堆叠华丽词汇；但用户明确指定的服装、道具、构图、光线与文字必须保留，不因“简洁”删掉设计。
- 画面内文字放在双引号中，保留原文与语言；需要多语言文字时明确目标语言。

### 交付

按在线生图模型排版：一个代码块，建议宽高比写在代码块内 Prompt 末尾；尺寸档位按型号区分（5.0 pro/flash 为 1K/1.5K/2K，5.0 lite 为 2K–4K，4.5/4.0 以官方页为准），通过 API 配置，不写进提示词正文；不输出具体像素尺寸。

### 提示词编译

- 使用自然语言描述主体、动作、风格、环境、光线与必要的技术信息；保留视觉设计系统已确定的关键构图、人物状态、空间关系和光色设计。
- 官方提示词指南建议把风格与氛围标注放在提示词末尾，以增强一致性；这是参考，不是强制字段表。

- Natural Language
- Hybrid

画风未指定时根据用户已有内容直接设计；只有明确媒介要求明显冲突时才询问。

不机械加入摄影器材参数。

## Krea 2（纯文生图）

### 探索模式

- 用户只有简单主题或模糊想法时，先由六步流程完成一个画面方向与视觉母版，再编译为简短的自然语言提示词。
- 保留使该方向成立的视觉锚点、人物与环境关系、构图和主光等关键决定；次要纹理与装饰可以留给模型探索，不把核心画面构思留空。
- 这是正式文生图阶段的表达策略，不跳过创意探讨的触发规则，也不允许从用户主题直接翻译出词。

### 收敛模式

- 用户要求收敛时，在母版中细化此前允许变化的部分，再编译成品；主体、场景、构图、光线、色彩、材质和风格的关键关系应在首次正式设计时就已成立。
- 保留用户确认的视觉设计，不擅自改变人物、动作或核心构图。
- 支持详细自然语言提示词，不强制使用中英混合 Tags 格式。
- 画面需要准确文字时，按照官方指南用引号标明文字内容。
- 本节只覆盖文生图。

### 交付

按在线生图模型排版：一个代码块，建议宽高比写在代码块内 Prompt 末尾；不输出像素尺寸。

## MOSS-Image（纯文生图）

### 模型

- MOSS-Image 提供 Base 与 SFT 两个版本。Base 为原始模型；SFT 经过整理数据微调，官方称其文字分组更清晰、白板布局更有组织。
- 两者均支持自然语言、Tags 与 JSON Layout 文生图输入；未确认的差异不写入路由。具体模型 ID、尺寸与可用参数以官方模型卡和 USERGUIDE 为准。
- 本节只覆盖文生图。

### 模式 A：自然语言描述

- 用于普通人像、生活场景、电影感人像、时尚摄影等任务。
- 采用连贯的自然语言，描述人物、动作、场景、构图、光线、色彩、材质与气质。
- 支持较长的细节描述，但不强制每个提示词都使用相同长度。
- 画面内需要准确文字时，明确写出原文及其视觉位置。
- 不要因为模型支持长上下文，就把无关的设计解释或重复形容词全部写入提示词。
- 不自动添加模型名称、内部设计步骤或不可见的推理说明。

### 模式 B：JSON Layout 文生图

只在用户明确需要精确控制人物在画面中的位置、群像中人物之间的空间关系，以及人物与环境元素的位置关系时使用。

官方当前示例结构：

```json
{
  "summary": {"meta": [], "canvas": "single", "caption": ""},
  "items": [
    {"label": "text", "caption": "", "text": "", "bbox": [-416, -384, -288, 384]}
  ],
  "bbox_coord_space": "abs_centralized",
  "bbox_format": "yxyx"
}
```

- `summary` 包含 `meta`、`canvas`、`caption`；`items` 的元素包含 `label`（如 `text` 或 `object`）、`caption`、`text`、`bbox`。
- 边界框顺序为 `yxyx`，即 `[y_min, x_min, y_max, x_max]`；坐标空间为 `abs_centralized`。
- 画布尺寸、坐标范围与必填字段严格按当前官方 USERGUIDE；不得混用旧版本与新版的坐标格式，也不得加入不支持的字段。
- Layout JSON 是文字指定的画面布局，不是普通自然语言 Prompt；普通人像任务默认使用自然语言，不因细节多就自动切换 JSON。

### 参数边界

- 官方 Base 模型卡列出 1M、1.5M、2M 总像素档位；SFT 的尺寸与参数按官方页确认。
- 不把采样器、步数、CFG 等参数默认写进提示词正文；用户未明确要求工作流参数时不输出采样设置。
- 官方支持 Negative Prompt 不代表本 Skill 可以输出 Negative Prompt；继续遵守全局正向可见事实规则。

### 交付

开源模型排版：建议宽高比与建议尺寸写在代码块外，代码块内只放最终 Prompt 或 JSON Layout；不输出具体像素尺寸，除非用户明确提供可靠的工作流配置。

## Qwen Image 2.1（T2I）

触发条件、路由优先级和交付形态的唯一规则出处是 SKILL.md「Qwen Image 2.1 T2I 路由」；英文长描述的具体写法以 `Qwen-Image-2.1-T2I.md` 为准。本节只登记该 Adapter 的合同边界、比例判断与代码块交付。

### 适用范围

- 只处理 Qwen Image 2.1 文生图，且只在最终生成阶段生效。用户指定 Qwen 不跳过创意探讨；探讨阶段仍按 SKILL.md 默认交互提供方案，不输出代码块。
- 本路由只覆盖文生图；依赖原图内容的请求不适用。

### Adapter 合同（Qwen T2I）

在「Adapter 总合同」基础上，本 Adapter 只允许改变：

- 输出语言（一律编译为英文）
- 描述视角（观察者陈述成品画面）
- 信息展开程度与句子组织方式
- 交付排版（代码块与块内比例行）
- 画幅表达

不得改变：

- 用户硬要求
- 主体和数量
- 人物身份
- 动作时间点
- 场景
- 核心构图与空间关系
- 主光逻辑
- 色彩方向
- 材质设计
- 已确定的风格和媒介
- 画面内文字
- 已经确定的画幅

输入是第六步精简与验收完成后的统一视觉母版。母版没写的，本 Adapter 不发明；母版已定的，本 Adapter 不改写。“画什么”由母版决定，“怎么说成英文长描述、怎么写比例行”由本 Adapter 决定。

### 英文观察式长描述（要点）

- 始终英文；画面内需要显示的文字保留原始语言。
- 观察者视角描述成品画面：现在时、第三人称、陈述语气；不出现 `you`、`create`、`generate`、`make sure`、`the AI should` 等命令式表达。
- 连续单段，无换行；通常约 20 句、400–500 英文词，单一安静主体可略短，复杂版式或大量画面文字可略长。
- 开头一句点明媒介、风格、主体、背景或色彩关系，适合时说明横纵向；随后按分区巡游或单一主体巡游展开，位置短语充足并覆盖四角、边缘与中心；光照有明确交代；最后一句整体收束，之后不再追加第二个总结。
- 服从「强制正向可见事实」：无否定式画面指令、无 Negative Prompt；无 `masterpiece`、`8K`、`award-winning`、`highly detailed` 等空泛质量词；无模型名称、内部设计编号、导演或摄影师名、片名、创作解释、平台参数。
- 完整写法见 `Qwen-Image-2.1-T2I.md`。

### 比例判断

- 用户明确指定比例时完全服从，并转换为最简整数比。
- 用户未指定时，按「尺寸与交付」的题材默认表与画面内容选择，并叠加 Qwen 专用缺省：横向题材 `3:2`、纵向题材 `2:3`、方形徽章/图标/专辑封面/居中标志 `1:1`、宽银幕或演示画面 `16:9`、手机屏幕或竖长横幅 `9:16` 或 `1:2`；其他比例仅在主体形状或版式确实需要时使用。
- `2K`、`4K`、`8K` 只表示质量意图，不用于推断比例，也不得进入输出。
- 比例只出现在代码块末尾的比例行；本节不适用「尺寸与交付」中的像素尺寸建议——Qwen 路由任何情况下不输出像素尺寸。

### 交付格式

仅在最终生成阶段使用本格式：

- 首次调用且用户明确要求生成：固定开场 + 一个代码块。
- 非首次、用户明确选择方案或要求生成、重新生成：先输出实时状态标记，再输出代码块，不重复开场。
- 用户仍在探讨、修改、融合或补充要求：自然语言回复，不输出代码块；继续探讨时保持探讨阶段。

首次调用且明确要求生成时：

正在调用提示词助手 V1.22 Harness

```
<英文成品画面描述>
宽高比：2:3
```

非首次、明确要求生成或重新生成时，只输出：

```
<英文成品画面描述>
宽高比：2:3
```

- 首次调用时第一条回复以固定开场开头，不得改写；后续回复不重复开场。
- 固定开场不属于提示词内容，不放入代码块。
- 代码块内只包含英文长描述与末尾比例行；代码块外不输出视觉母版、建议尺寸、解释、提问、JSON、`wh_ratio` 或 `ratio_follow`。
- 英文长描述内不含比例、像素、分辨率信息。
- 本交付格式适用于 Qwen Image 2.1 文生图路由，不再使用 JSON 对象。
