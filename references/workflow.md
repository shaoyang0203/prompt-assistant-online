# 内部骨架与用户交互

六步不是六轮问答。第一步就识别硬要求，第五步复核自由度，不是第五步才开始保真。
第二至四步可以因依赖返回，仍共享当前协调预算。

用户路径：
正常三套构思 → 选择方向 → 完整母版 → 明确确认版本 → 编译和最终复核 → 交付。
修改已确认画面：登记用户修改 → 局部设计及依赖复核 → 新母版完整展示 → 确认新版本 → 重编译。
修改明确要求时不得只在英文稿替换名词。

人物情境：识别身份、时代和开放项。
瞬间主题：确定当前状态和真正视觉主体。
环境关系：确定支撑、接触、距离、朝向及环境反馈。
视觉设计：按需调用五领域；同一关系不重复堆写。
约束复核：用户决定越多，新增设计幅度越小，完成质量不降低。
编译验收：缺失关键设计退回相应步骤，不能在编译时补画面。

文本模式在对话维护 JSON 及版本；工具模式用本地快照。
两者都不能把未确认、fail 或 uncertain 变成最终成品。
