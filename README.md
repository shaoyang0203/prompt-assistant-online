# Prompt Assistant Online V1.2.0

## 项目简介

Prompt Assistant Online V1.2.0 是面向人像文生图的提示词助手。

核心流程是：先与用户讨论创意方案，再进行视觉设计，最后编译为目标图像模型适用的提示词。它不是收到一句话就直接扩写的生成器，也不是摄影术语堆叠器。

当前范围以人物与人像视觉创作为核心。非人像题材按通用提示词处理，不套用人像默认主体，也不提供专门的非人像知识模块。

## 核心功能

- **创意探讨**：用户给主题后，先提供有实质差异的中文方案；支持选择、修改、融合与继续讨论。只有明确要求生成后才进入最终交付。
- **视觉设计系统**：七类知识与固定六步流程，覆盖人物情境、主题构思、动作互动、构图空间、光色材质、审美语言与质量控制。
- **默认主体**：按属性逐项补全。用户未指定的属性使用默认值；用户明确指定的性别、年龄、体型、国籍等属性优先；与指定属性冲突的默认项不继承。
- **用户要求优先**：用户硬要求高于默认主体和风格系统；已确认的关键画面设计在正式生成中保持保真。
- **模型适配**：根据目标模型采用不同的提示词编译方式、专用参数与交付格式。不同模型的语法不互相套用。
- **纯文生图**：当前模型路由只覆盖文生图；不提供图生图、局部重绘、扩图、换装、换脸或多图融合工作流。

## 使用方式

1. Skill 首次被调用时，第一条助手回复以“正在调用提示词助手 V1.2”开头。后续探讨与生成回复不重复开场，除非用户重新启动 Skill。
2. 用户输入主题后，默认进入创意探讨：通常提供 3—5 个中文创意方案；方向明确时提供 1—2 个变体或复述确认。
3. 用户可以选择方案、修改服装或环境、融合多个方案，或继续讨论。这些操作不会自动触发最终生成。
4. 只有用户明确选择方案作为最终方向，或明确提出生成意图时，才进入六步视觉设计与最终提示词交付。
5. 正式生成时，六步流程在内部执行，不要求用户逐项填写表格，也不向用户展示冗长的内部分析。
6. 默认只交付最终 Prompt；用户明确要求“通用版”“给我母版”或“不要模型适配”时，才输出视觉母版。

本地使用时，把 `prompt-assistant-online-v1-2-0/` 目录放进技能目录即可，`SKILL.md` 为入口。在线粘贴时，正式设计需要完整读取 `视觉设计系统/00-总纲.md` 与 `01—07` 七个模块，并追加目标模型 Adapter；Qwen Image 2.1 另需 `Qwen-Image-2.1-T2I.md`。

## 模型支持范围

当前 `references/Adapter与交付.md` 实际包含以下路由：

| 路由 | 类型与范围 |
|---|---|
| GPT Image | GPT Image 2.5 Sunburst / Flare、GPT Image 2；纯文生图 |
| Grok Imagine | `grok-imagine-image-2.0`；纯文生图 |
| Midjourney | V8.2 默认，V8.1、V7、V6.1、V6、Niji 7 可用；纯文生图 |
| Gemini Image | Nano Banana Pro、Nano Banana 2、2.1、2 Lite；纯文生图 |
| Seedream | 5.0 pro / flash / lite，4.5、4.0；纯文生图 |
| FLUX.2 | pro、flex、dev、max、klein；静态文生图 |
| SDXL 系列 | SDXL 通用、Pony、Illustrious、Anima |
| Z-Image | Z-Image-Turbo、Z-Image（基础文生图模型） |
| Krea 2 | 探索模式与收敛模式；纯文生图 |
| MOSS-Image | Base、SFT；自然语言或可选 JSON Layout |
| Qwen Image 2.1 | 文生图专用路由；英文观察式长描述 |
| 未登记模型 | 通用兜底，不猜测专用语法、参数或尺寸 |

说明：

- **FLUX.3 不列为静态文生图路由**。按当前官方 skills 文档，FLUX.3 属视频生成系列，本文件不建立 FLUX.3 路由。
- **不宣传编辑能力**。图像编辑、局部重绘、扩图、换装、换脸、多图融合与参考图编辑工作流不在当前路由范围内。SKILL 中的参考图分责是输入判断原则，不等同于编辑路由。
- **API 参数与提示词分开**。`size`、`quality`、`background`、`aspect_ratio`、`resolution`、`n` 等是请求参数；只有用户明确要求 API 配置时才单独提供，不写入提示词正文。
- **交付格式因模型而异**。在线模型通常是一个代码块、比例写在块内末尾；Z-Image、MOSS-Image 等开源模型通常把比例与尺寸写在代码块外；Qwen Image 2.1 使用英文观察式描述代码块加块内比例行，不使用 JSON。具体以 Adapter 对应章节为准。

## 与 V1.1.0 的主要区别

- **新增创意探讨优先的交互机制**：先提供方案、支持修改与融合，明确选择或明确要求生成后才出词。
- **取消 DPCRS 框架名称**：不再以 D/P/C/R/S 五段式组织设计知识，改为七类「视觉设计系统」。
- **建立七类知识与六步固定流程**：替代旧版分散的设计清单。
- **取消具体姿势黑名单**：保留“避免缺乏设计意图的机械重复”的质量原则。
- **取消独立视觉退火机制**：受约束的精简与完整性检查合并到第六步。
- **调整模型路由与交付方式**：新增并拆分 GPT Image、Grok Imagine、Gemini、Seedream、FLUX.2、Krea 2、Z-Image、MOSS-Image 等文生图路由；Qwen Image 2.1 改为代码块交付，不再使用旧版单行 JSON。
- **新增默认主体机制**：按属性逐项补全，并处理用户指定属性、年龄边界与不兼容默认项。

V1.1.0 原包保留，未在本版中修改。

## 测试与限制

- **静态文件检查**：已核对当前目录结构、七类模块、六步流程、纯文生图路由与文件引用。静态检查只证明文件内容与结构一致，不证明模型实际执行效果。
- **当前执行引擎测试**：`验收测试报告.md` 记录了 19 组当前执行引擎行为测试，覆盖创意探讨、修改与融合、明确生成、默认主体可见性、年龄边界、GPT 与 Qwen 交付等用例。这些测试早于本轮纯文生图路由重写，新路由尚未独立复测。
- **真实目标模型测试未执行**：GPT Image、Grok Imagine、Midjourney、Gemini Image、Seedream、FLUX.2、SDXL 系列、Z-Image、Krea 2、MOSS-Image 与 Qwen Image 2.1 均未在对应模型上运行；真实出图质量、跨模型表现、Qwen 出词与出图、LM Studio 复跑、跨引擎复跑均未验证。
- **未验证不等于失败**：规则写入文件、静态检查通过或当前引擎能按规则回复，都不等于目标模型已经正确执行。实际效果需要在目标环境中测试。
