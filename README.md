# Prompt Assistant Online V1.3.0 Harness

本版统一命名为 **V1.3.0-harness**，在 1.22 基础上修复定向删除、偏好冲突与重复、无效快照增长、导入状态副作用及入口缓存污染，并统一相关交付规则。实验记录按唯一 ID 对齐后核验，顺序变化不再误报失败；缺失、重复及内容变化仍会被检出。默认把用户描述作为素材与约束，先完成画面方案，再由母版编译 Prompt；短词、抽卡和 Krea 2 探索表达不能跳过设计。明确仅翻译、完整画面迁移及局部修改仍按用户限定范围处理。

设计协议见 [素材到画面的设计合同](references/design-contract.md)。

面向人像文生图的提示词设计 Skill：**先探讨创意，再完成视觉设计，最后生成适合目标模型的提示词。**

Harness 在 V1.2 VIP 的基础上，加入独立的反馈、偏好、优化实验、修改日志和迁移机制。你可以逐步积累自己的审美偏好，也可以在有证据、经过验证的前提下积累设计经验。

本版为本地构建的 1.3.0-harness，尚未发布 GitHub · [发布说明](发布说明.md) · [Harness 使用说明](references/harness-help.md) · [数据格式与迁移](harness/README.md)

## 能做什么

### 先讨论，再生成

输入人物、场景或画面想法后，助手先用自然语言讨论创意方案。你可以选择方向、修改细节、融合方案，也可以继续讨论。

明确选择最终方向或要求生成后，助手依次完成六步设计：

1. 人物与情境建模。
2. 确定画面瞬间与表达主题。
3. 建立人物与环境的关系。
4. 完成构图、空间、光线、色彩与材质设计。
5. 确定约束程度与创作空间。
6. 编译提示词并检查遗漏、冲突和冗余。

七类视觉知识继续支撑这一流程。用户明确要求和已确认的关键设计保持优先，模型适配负责整理表达，不重新改变画面。

### 记录个人偏好

支持四档反馈：**特别喜欢、喜欢、一般、厌恶**。

总体评价和具体设计特点分开记录。只说“特别喜欢”不会被理解成喜欢这张画面的所有元素；“一般”也不会被解释为厌恶。Agent 的推断会明确标记为弱证据。

偏好保留适用语境、模型范围和来源。一次方案意见不会自动变成永久偏好；模型特定问题也不会自动扩展到所有模型。永久硬约束与当前要求冲突时，先确认如何处理。

可以查看、纠正、停用或删除偏好，也可以分别暂停学习、停止应用普通历史偏好。

### 验证后积累设计经验

个人偏好回答“这个用户喜欢什么”，设计经验回答“什么方法在什么条件下有效”。两者独立管理。

递归优化按以下流程开展：

**收集反馈 → 区分问题类型 → 提出候选 → 前后对照 → 其他题材验证 → 验收与授权 → 保存经验或拒绝晋级。**

默认候选门槛为至少三个独立方案的明确设计反馈，涉及两类场景。测试还需要未参与规则形成的其他题材，并检查用户要求是否完整、创意空间是否受损、其他任务是否退化。门槛可配置。

通过验收且获得明确授权后，经验才会写入独立可变数据。失败、拒绝和回滚也有记录。优化器不会自动覆盖核心 Skill、固定流程或视觉设计知识。

## 开始使用

1. 使用本次本地交付的 **`V1.3.0-harness.zip`**。
2. 解压后保留完整的 `prompt-assistant-online-v1-3-0-harness/` 目录，按照所用 Agent 平台的本地 Skill 安装方式导入。入口为 `SKILL.md`，引用文件和脚本需要一同保留。
3. 调用提示词助手，描述想设计的画面。例如：“我想设计一位成年女性在雨后街边咖啡馆外的环境人像，先讨论几个方向。”
4. 首次调用时查看实际环境检测结果，再决定是否开启递归优化。不开启也可以正常讨论和生成提示词。

核心提示词设计由接入 Skill 的 Agent 执行。Harness 脚本要求 **Python 3.10+、执行能力和可跨会话保留的文件读写空间**，运行时仅使用 Python 标准库。

仅将文本粘贴进聊天框，不代表该平台已经具备持久化学习能力。环境不可用时，仍可继续设计和临时分析反馈，但不能宣称已经保存。

## 启动状态与开关

当前对话首次调用的第一行是：

> 正在调用提示词助手 V1.3.0 Harness

第二行根据真实检测结果显示以下状态之一；后续回复继续显示状态，不重复固定开场：

| 状态 | 含义 |
|---|---|
| `[递归优化 --开]` | 允许按证据门槛开展候选优化和实验；写入生效经验仍需明确授权 |
| `[递归优化 --关]` | 不开展新的自动优化；仍可使用已有有效经验，并按 VIP 学习设置处理个人反馈 |
| `[递归优化 --不可用]` | 无法验证可靠的持久化读写能力，会说明实际原因 |

首次安装默认关闭。首次调用会在环境可用时询问是否开启；未回答保留已保存的状态，不擅自切换。

可以直接说：

- `递归优化 --开`
- `递归优化 --关`
- “解释递归优化。”
- “为什么递归优化不可用？”

环境检测会实际写入、同步、重读、比较和清理临时文件，并校验业务数据、保存独立健康状态；首次初始化或配置修复才创建快照。只有保存核验成功，才确认开关或反馈已保存。

## 反馈与日常管理

你可以在提示词或出图反馈中指出具体部分，例如：

- “特别喜欢这次人物和环境的互动，以后类似场景也参考这个方向。”
- “整体一般，背景道具太多，这次减少一些。”
- “这个动作在当前模型中反复出错，请记录这个模型的限制。”

助手会区分文字评价与实际出图反馈；未取得图像或可靠反馈时，不会声称已经验证出图改善。出现意外元素而解决方向不明确时，会给出针对当前场景的选项，等待选择。

管理请求可以使用自然语言：

| 请求 | 作用 |
|---|---|
| 查看／纠正我的个人偏好 | 查看已有记录或按明确要求修正 |
| 暂停学习 | 停止新增案例，仍可参考已有偏好 |
| 停用已有偏好 | 停止应用普通历史偏好；永久硬约束另行确认处理 |
| 忘记这次反馈／清空个人偏好 | 经确认删除当前目标及关联记录／清空当前数据；历史和备份保留 |

VIP 学习设置、应用偏好设置、递归优化开关和经验写入授权分别控制。

## 数据保存、导出与迁移

个人数据保存在 Skill 目录之外。默认位置为当前操作系统用户主目录下的 **`.prompt-assistant/harness`**；也可通过 `--data-dir` 或 `PROMPT_HARNESS_DATA_DIR` 指定独立目录。运行时会显示实际位置，不同用户应使用各自目录。

官方基础规则与用户数据分开，升级 Skill 时无需用新模板覆盖个人记录。根目录的 `用户偏好.md` 仅为空白 VIP 迁移模板，不是 Harness 的运行时数据源。

在具备执行和文件访问能力的环境中，可以直接请求：

| 请求 | 导出内容 |
|---|---|
| 导出我的个人偏好文件 | 独立 `user_preferences.json`，包含偏好、约束及反馈证据 |
| 导出我的 Harness 修改记录和优化经验 | 经验、候选、实验与历史日志 ZIP |
| 导出完整 Harness 迁移包 | 个人偏好和 Harness 数据的完整迁移 ZIP |
| 导入我的 Harness 迁移包 | 校验、备份、合并、去重并报告冲突 |

导入不覆盖新版核心，也不会自动开启引擎或晋级旧候选。当前支持数据格式 1，以及 1.2.0-harness、1.2.1-harness、1.22、1.3.0-harness 的对应来源身份；旧 VIP Markdown 需先核对并显式转换。详细命令见 [数据格式与迁移](harness/README.md)。

迁移包可能包含私人创意、反馈原文和实验内容，应与公开发行包分开保管。forget 必须提供存在的 ID 和明确确认，仅删除当前目标及关联记录；共享证据和无关记录保留。clear 经确认清空当前偏好与派生数据。两者均保留历史 generation、审计文件和备份，不代表彻底擦除历史原文。外部另存的导出包由用户自行管理。

## 模型适配与任务范围

现有适配文档涵盖 GPT Image、Grok Imagine、Midjourney、Gemini Image、Seedream、FLUX.2、SDXL／Pony／Illustrious／Anima、Z-Image、Krea 2、MOSS-Image 和 Qwen Image 2.1。具体表达与交付规则见 [Adapter 与交付](references/Adapter与交付.md)。这些是提示词编译路由，不代表本项目已经在所有目标模型上完成出图测试。

当前以人物与人像**文生图**为核心。非人像题材按通用提示词处理；参考图可用于明确身份或视觉方案，但本 Skill 不提供图像编辑、换脸、局部重绘、扩图等执行工作流，也不会自动调用生图服务。

## 测试状态与限制

V1.3.0 Harness 补丁验收时，在 Windows、Python 3.13.11 环境下完成 **129 项自动化测试，全部通过**。覆盖环境检测、开关、反馈、范围约束、候选门槛、回滚、导入导出、命令行入口与设计协议文件完整性。只读拒绝、读取失败、清理失败等异常使用受控故障注入验证。

同时完成 Skill 结构校验、文件引用与数据格式检查，以及发行 ZIP 的完整性和解包执行验证。本版结果以 `harness/test-results.json` 与 `交付报告.md` 为准；仓库中若保留普通 V1.2 的旧验收报告，应作为对应版本的历史记录阅读。

这些测试验证存储和流程逻辑，**不证明真实出图质量已经提高**。实际图像模型效果、其他操作系统、第三方附属存储、网络盘及云同步持久性尚未验证。Harness 也不是常驻后台学习服务；语义理解、评价依据和视觉判断仍由 Agent 与用户负责。

## 1.3.0-harness 累计修复

修复反馈布尔标记误判、未知模型版本越界、首次保存失败重试、非有限回归参数、导入反馈证据冲突传播及实验排序导致的错误失败报告。迁移明确兼容 1.2.0-harness、1.2.1-harness 、1.22 和当前 1.3.0-harness，不预先接受未来版本。详情见 [发布说明](发布说明.md)。

### 设计行为验证范围

[16 个行为回归任务与 4 个反例](tests/design-cases.json) 覆盖主题探讨、直接生成、长描述、MJ 短词、Krea 2 简洁表达、可选素材、迁移、仅翻译、抽卡、局部修改、剪纸和静态肖像。

[文本产物与自审记录](harness/design-review.json) 由同一编辑 Agent 编写和检查，属于合同可执行性的示例验证；不计入 129 项自动化测试，不是独立盲测，未在 Grok Bot 实际宿主复测，未验证出图质量。给被测模型运行时只提供原始任务、上下文和技能，产出后再评审，避免把参考答案当成测试输入。

## Qoder 测试反馈：首次设计前确认模型

修复新聊天未选模型就开始设计的问题：没有本次对话中明确的目标生图模型或通用版/母版选择时，先询问并等待，再开始方案与六步设计。直接生成不豁免；已指定模型、明确通用版及仅翻译不重复问。聊天宿主名称不代表生图模型。新增 D13—D16 文本行为样例，仍属同一编辑 Agent 自审，未声称 Qoder 实际复测通过。

### Grok 网页端宽高比位置修正

依据用户 2026-10-25 的实际使用反馈，Grok 推荐比例放在提示词代码块外，并由输入框外侧的比例控件选择；不再以 Prompt 文字设置比例。GPT 规则独立保留。此修正已同步主规则、Adapter 和交付检查。

### 本轮收录

黑金西域幻想舞姬已合并到 [审美与视觉语言](references/视觉设计系统/06-审美与视觉语言.md) 的「呈现方式参考」，与暖金古风夜宴、克制暖金宫廷并列，不再单独设文件。保留人物服饰与覆头披纱连接关系，场景、光线和构图按当前需求设计。Grok 网页端推荐宽高比在代码块外、由界面选择的修正继续保留；GPT 规则独立。

## 1.3 导入与状态规则

纯偏好 JSON 导入只合并偏好及关联证据并记录迁移日志，保留目标环境的 enabled、authorized_overrides、sessions、健康时间及 learning/apply。Harness 历史包和完整包导入仍关闭引擎与覆写授权、重置会话并检测环境；配置位置、门槛和 learning/apply 不从来源迁移。三种导入均先备份。

健康时间保存于外部 health.json；仅审计变化写入与当前 generation 关联的轻量日志，下一次业务提交再纳入完整快照。重复检查、重复开关和暂停学习期间的反馈不创建无效快照。旧快照和备份不自动清理。
