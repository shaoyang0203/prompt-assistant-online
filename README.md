# Prompt Assistant Online V1.2 Harness

面向人像文生图的提示词设计 Skill：**先探讨创意，再完成视觉设计，最后生成适合目标模型的提示词。**

Harness 在 V1.2 VIP 的基础上，加入独立的反馈、偏好、优化实验、修改日志和迁移机制。你可以逐步积累自己的审美偏好，也可以在有证据、经过验证的前提下积累设计经验。

[下载 V1.2 Harness](https://github.com/shaoyang0203/prompt-assistant-online/releases/tag/v1.2.0-harness) · [发布说明](发布说明.md) · [Harness 使用说明](references/harness-help.md) · [数据格式与迁移](harness/README.md)

## 能做什么

### 先讨论，再生成

输入人物、场景或画面想法后，助手先用自然语言讨论创意方案。你可以选择方向、修改细节、融合方案，也可以继续讨论。

明确选择最终方向或要求生成后，助手依次完成六步设计：

1. 人物与情境建模。
2. 确定画面瞬间与表达主题。
3. 建立人物与环境的关系。
4. 完成构图、空间、光线、色彩与材质设计。
5. 确定约束程度与创作空间。
6. 编译提示词并检查遗漏、冲突和冗余。

七类视觉知识继续支撑这一流程。用户明确要求和已确认的关键设计保持优先，模型适配负责整理表达，不重新改变画面。

### 记录个人偏好

支持四档反馈：**特别喜欢、喜欢、一般、厌恶**。

总体评价和具体设计特点分开记录。只说“特别喜欢”不会被理解成喜欢这张画面的所有元素；“一般”也不会被解释为厌恶。Agent 的推断会明确标记为弱证据。

偏好保留适用语境、模型范围和来源。一次方案意见不会自动变成永久偏好；模型特定问题也不会自动扩展到所有模型。永久硬约束与当前要求冲突时，先确认如何处理。

可以查看、纠正、停用或删除偏好，也可以分别暂停学习、停止应用普通历史偏好。

### 验证后积累设计经验

个人偏好回答“这个用户喜欢什么”，设计经验回答“什么方法在什么条件下有效”。两者独立管理。

递归优化按以下流程开展：

**收集反馈 → 区分问题类型 → 提出候选 → 前后对照 → 其他题材验证 → 验收与授权 → 保存经验或拒绝晋级。**

默认候选门槛为至少三个独立方案的明确设计反馈，涉及两类场景。测试还需要未参与规则形成的其他题材，并检查用户要求是否完整、创意空间是否受损、其他任务是否退化。门槛可配置。

通过验收且获得明确授权后，经验才会写入独立可变数据。失败、拒绝和回滚也有记录。优化器不会自动覆盖核心 Skill、固定流程或视觉设计知识。

## 开始使用

1. 从 [Release 页面](https://github.com/shaoyang0203/prompt-assistant-online/releases/tag/v1.2.0-harness) 下载附件 **`V1.2.0-harness.zip`**。
2. 解压后保留完整的 `prompt-assistant-online-v1-2-0-harness/` 目录，按照所用 Agent 平台的本地 Skill 安装方式导入。入口为 `SKILL.md`，引用文件和脚本需要一同保留。
3. 调用提示词助手，描述想设计的画面。例如：“我想设计一位成年女性在雨后街边咖啡馆外的环境人像，先讨论几个方向。”
4. 首次调用时查看实际环境检测结果，再决定是否开启递归优化。不开启也可以正常讨论和生成提示词。

核心提示词设计由接入 Skill 的 Agent 执行。Harness 脚本要求 **Python 3.10+、执行能力和可跨会话保留的文件读写空间**，运行时仅使用 Python 标准库。

仅将文本粘贴进聊天框，不代表该平台已经具备持久化学习能力。环境不可用时，仍可继续设计和临时分析反馈，但不能宣称已经保存。

## 启动状态与开关

当前对话首次调用的第一行是：

> 正在调用提示词助手 V1.2 Harness

第二行根据真实检测结果显示以下状态之一；后续回复继续显示状态，不重复固定开场：

| 状态 | 含义 |
|---|---|
| `[递归优化 --开]` | 允许按证据门槛开展候选优化和实验；写入生效经验仍需明确授权 |
| `[递归优化 --关]` | 不开展新的自动优化；仍可使用已有有效经验，并按 VIP 学习设置处理个人反馈 |
| `[递归优化 --不可用]` | 无法验证可靠的持久化读写能力，会说明实际原因 |

首次安装默认关闭。首次调用会在环境可用时询问是否开启；未回答保留已保存的状态，不擅自切换。

可以直接说：

- `递归优化 --开`
- `递归优化 --关`
- “解释递归优化。”
- “为什么递归优化不可用？”

环境检测会实际写入、同步、重读、比较和清理临时文件，并验证数据快照保存。只有保存核验成功，才确认开关或反馈已保存。

## 反馈与日常管理

你可以在提示词或出图反馈中指出具体部分，例如：

- “特别喜欢这次人物和环境的互动，以后类似场景也参考这个方向。”
- “整体一般，背景道具太多，这次减少一些。”
- “这个动作在当前模型中反复出错，请记录这个模型的限制。”

助手会区分文字评价与实际出图反馈；未取得图像或可靠反馈时，不会声称已经验证出图改善。出现意外元素而解决方向不明确时，会给出针对当前场景的选项，等待选择。

管理请求可以使用自然语言：

| 请求 | 作用 |
|---|---|
| 查看／纠正我的个人偏好 | 查看已有记录或按明确要求修正 |
| 暂停学习 | 停止新增案例，仍可参考已有偏好 |
| 停用已有偏好 | 停止应用普通历史偏好；永久硬约束另行确认处理 |
| 忘记这次反馈／清空个人偏好 | 按明确请求清理数据，并先说明关联历史清理范围 |

VIP 学习设置、应用偏好设置、递归优化开关和经验写入授权分别控制。

## 数据保存、导出与迁移

个人数据保存在 Skill 目录之外。默认位置为当前操作系统用户主目录下的 **`.prompt-assistant/harness`**；也可通过 `--data-dir` 或 `PROMPT_HARNESS_DATA_DIR` 指定独立目录。运行时会显示实际位置，不同用户应使用各自目录。

官方基础规则与用户数据分开，升级 Skill 时无需用新模板覆盖个人记录。根目录的 `用户偏好.md` 仅为空白 VIP 迁移模板，不是 Harness 的运行时数据源。

在具备执行和文件访问能力的环境中，可以直接请求：

| 请求 | 导出内容 |
|---|---|
| 导出我的个人偏好文件 | 独立 `user_preferences.json`，包含偏好、约束及反馈证据 |
| 导出我的 Harness 修改记录和优化经验 | 经验、候选、实验与历史日志 ZIP |
| 导出完整 Harness 迁移包 | 个人偏好和 Harness 数据的完整迁移 ZIP |
| 导入我的 Harness 迁移包 | 校验、备份、合并、去重并报告冲突 |

导入不覆盖新版核心，也不会自动开启引擎或晋级旧候选。当前支持数据格式 1 和声明兼容的 `1.2.x-harness` 来源；旧 VIP Markdown 需先核对并显式转换。详细命令见 [数据格式与迁移](harness/README.md)。

迁移包可能包含私人创意、反馈原文和实验内容，应与公开发行包分开保管。忘记或清空操作会清理关联证据、全部派生实验经验以及管理中的旧快照和备份；外部另存的导出包由用户自行管理。

## 模型适配与任务范围

现有适配文档涵盖 GPT Image、Grok Imagine、Midjourney、Gemini Image、Seedream、FLUX.2、SDXL／Pony／Illustrious／Anima、Z-Image、Krea 2、MOSS-Image 和 Qwen Image 2.1。具体表达与交付规则见 [Adapter 与交付](references/Adapter与交付.md)。这些是提示词编译路由，不代表本项目已经在所有目标模型上完成出图测试。

当前以人物与人像**文生图**为核心。非人像题材按通用提示词处理；参考图可用于明确身份或视觉方案，但本 Skill 不提供图像编辑、换脸、局部重绘、扩图等执行工作流，也不会自动调用生图服务。

## 测试状态与限制

V1.2 Harness 开发验收时，在 Windows、Python 3.13.11 环境下完成 **72 项自动化测试，全部通过**。覆盖环境检测、开关、反馈、范围约束、候选门槛、回滚、导入导出和命令行入口。只读拒绝、读取失败、清理失败等异常使用受控故障注入验证。

同时完成 Skill 结构校验、文件引用与数据格式检查，以及发行 ZIP 的完整性和解包执行验证。本版结果以 `harness/test-results.json` 与 `交付报告.md` 为准；仓库中若保留普通 V1.2 的旧验收报告，应作为对应版本的历史记录阅读。

这些测试验证存储和流程逻辑，**不证明真实出图质量已经提高**。实际图像模型效果、其他操作系统、第三方附属存储、网络盘及云同步持久性尚未验证。Harness 也不是常驻后台学习服务；语义理解、评价依据和视觉判断仍由 Agent 与用户负责。
